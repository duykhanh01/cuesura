# Keep capability denial in bwrap's descendants

**Status: superseded by [ADR-0004](0004-isolated-bwrap-baseline.md).** The content below
records a historical decision; the AppArmor child stack is no longer a universal prerequisite of v1. The exception
condition for the internal sandbox is kept and restated in ADR-0004.

Code run by an agent can exec `/usr/bin/bwrap` from read-only `/usr`, so the profile was chosen following the `bwrap-userns-restrict` mechanism of AppArmor v4.0.2: bwrap sets up namespaces but descendants always carry the `cusr-bwrap-child` stack with capability denial, including via re-exec/copy; an `unconfined + userns` profile that does not restrict descendants is not accepted, and the template still allows userns so it does not promise to forbid every namespace. S0.1 must still test the enabled internal sandbox on each Claude/Codex version and record real evidence; if capability denial makes nesting fail, a **conditional exception for the internal OS sandbox layer** is allowed via settings/sandbox mode when the outer sandbox with the same profile/kernel/binary/mount layout has proven filesystem/PID/secret/canary/capability isolation, the harness's tool permissions/approval stay intact and negative fixtures confirm they are still denied, and the configuration explicitly chosen by the owner is frozen/recorded in the manifest and invocation. The internal layer is then defense in depth on top of the verified outer boundary; the exception grants no extra capability, does not waive the constitution's permission/approval/secret rules, does not allow `--dangerously-*`, permission bypass or automatic fallback when a tool fails, and expires when the proof/config/version no longer matches. If the outer proof or permission fixture fails, managed policy requires the internal sandbox, or that version has no mode that disables the OS sandbox independently of permissions, the gate stays closed to review an alternative isolation approach per the [runbook](../../deploy/README.md); the profile is loaded only by an admin after review, keeps host sysctls, and discloses its effect on every application that calls `/usr/bin/bwrap`.
