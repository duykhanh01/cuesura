# Isolated rootless bwrap as the baseline for feature 002

**Status: baseline superseded by [ADR-0005](0005-native-harness-permissions.md) on 2026-11-01. The content below is a historical decision, accepted on 2026-10-28; it replaced [ADR-0003](0003-bwrap-child-capabilities.md) on the baseline mechanism.** The slice 0 gate is still BLOCKED; this decision changes the verification criteria, it is not evidence that S0.1–S0.3 have passed.

ADR-0003 made an AppArmor child stack denying capabilities a pass condition on every host, conflating two different goals: keeping Cuesura's filesystem/PID/secrets out of the agent's reach and reducing kernel surface inside child namespaces. The ABI 4.0 profile requires Ubuntu 24.04 or AppArmor 4 userspace, attaches to `/usr/bin/bwrap` and so affects other applications, and did not yet compile on the Ubuntu 22.04/WSL2 in use. The 360-check experiment (specs/002-task-to-green-pr/sandbox-reassessment.md) showed that re-exec/copy of bwrap and raw userns with nonzero CapEff still do not reopen host root, Git metadata or read-only areas on a minimal layout; this is a counterexample to the assumption that "capabilities in a child namespace mean escaping the boundary", and does not prove resistance to kernel exploits or equivalence of hardening.

Decision: the automated task-to-green-PR flow uses **Isolated**, wrapping the whole harness and repo-controlled setup/gate/autofix in rootless bwrap, with the runner in a transient systemd user unit per [ADR-0002](0002-systemd-runner-lifetime.md). Ubuntu 24.04, AppArmor 4 or the Cuesura child stack are not required; the old profile remains only as optional hardening reviewed by an admin, with its own evidence. S0.1 checks security outcomes: mount/PID/secret/control/FD/socket, write limits per role, path races, re-exec/copy/raw-userns/remount/unmount and ownership/cgroup on the exact host/layout/binary; keep no-new-privileges, cap drop and host policy. A child userns or nonzero CapEff is not by itself a failure if it does not cross the boundary. Hosts that restrict userns still need provisioning reviewed by an administrator; doctor does not sudo, change sysctls, override managed policy or run unsandboxed.

In Isolated, the harness's **internal** sandbox is on by default (`internal_required`); this is not a Native-only mode. The `external_verified` exception from ADR-0003 is kept, only when the native internal sandbox has been tried and failed, the outer proof and permission/approval negative fixtures pass, the owner allows it in trusted config, and hashes/version/layout still match; it does not override managed policy, bypass permissions, use `--dangerously-*` or silently fall back per tool call. When native fails and the binary has no mode that disables the OS sandbox independently of permission/approval, the binding is blocked.

V1 has only a small `SandboxProvider` port and one bwrap implementation; no registry/plugin framework, no key to choose a backend. The constitution's trust boundary and [SPEC §15](../../SPEC.md), fail-closed doctor and `internet_outbound` network stay unchanged.

Rejected alternatives: **Native-only as the default** (worktree + the harness's sandbox/permissions) because the Claude sandbox only wraps the shell while Read/Edit/Write, hooks and MCP run outside that layer, the scope differs by vendor, and setup/gate/autofix spawned by Cuesura are not covered by any harness sandbox; so it cannot prove that orchestration secrets stay out of the agent's reach in unattended runs. Native-only may be studied later for interactive sessions but must not be opened to the automated runner. **Keeping AppArmor 4 mandatory** because the installation cost and system-wide impact are disproportionate to the extra hardening once the boundary is checked directly. **Container/VM by default** because it adds an engine and operational dependencies before the v1 threat model requires kernel isolation. **Forbidding child namespaces via seccomp/`--disable-userns`** because bwrap 0.6.1 does not have that flag and it may break the harness's internal sandbox; reconsider only when the threat model demands it and there is a compatibility test.

Consequences: less kernel hardening than the ADR-0003 configuration, which must be stated plainly in reports rather than reported as equivalent. The manifest records `isolation_mode=isolated`, `provider=bwrap` and the AppArmor label/profile if any as host data. The spec, plan/research, contracts, spike guide/report, tasks and [runbook](../../deploy/README.md) are synced with this decision; T002 fixes the prototype message that still requires the child stack, T006 adds the missing proofs.
