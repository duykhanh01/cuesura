# Put the runner in its own systemd unit

The runner must survive both a SIGKILL of the foreground daemon and a stop/restart of the daemon service, while `spawn({detached:true})` does not move the process out of the cgroup that systemd stops; feature 002 therefore uses `node:child_process.spawn` to call `systemd-run --user`, creating a separate transient service per operation ID, without attaching `PartOf`/`Requires` to the daemon and without restarting the agent automatically. Depending on the systemd user manager was chosen over two supervision backends or loosening the daemon's `KillMode` because a separate unit keeps ownership, the ability to re-adopt, and stopping the whole process tree; doctor must check that the manager is actually reachable, on WSL check the `[boot] systemd=true` configuration and the state after a distro restart, and the survive-stop/restart fixture must pass in slice 0 before building the runtime. This is a baseline adjustment scoped to feature 002 under [SPEC §§12.1/17.2](../../SPEC.md), and does not waive the single-writer, permission or effect-deduplication requirements; attempt directories/files keep the SPEC §12.1 contract.
